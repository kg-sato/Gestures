# Camera Experiments frontend workflow

The user approved six selectable live-camera effects replacing jelly sculpting. The active design is [six-camera-effects-proposal.md](../design/six-camera-effects-proposal.md); references and observed pipelines are in [wxll-hx-video-study.md](../design/wxll-hx-video-study.md). The earlier jelly and Donut/Catch descriptions are historical.

Preserve the local MediaPipe worker, one-inference back pressure, stable identities, same-device camera lifecycle and private video. No Studio, manual model editor, FPS/debug HUD or bottom status controls. A top/side selector for the six effects is explicitly approved. The introduction appears once per page load and cannot reopen until reload.

Load applicable project make-ui/make-motion/make-creative skills and the shared frontend workflow. References inside those skills to donuts, sculpting or an editor do not override the approved camera-effects design. Retain Gestures' cream paper, plum ink and peach/mint control identity; render effects carry their own palettes. App-screen taste findings are review leads, not a mandate to replace the camera with a dashboard. Small treatment labels and swatches have a functional selection role; the established ink borders and intro shadow are deliberate brand choices.

Run `powershell -NoProfile -File scripts/test-frontend-skills.ps1`, `npm test` and `npm run build`. Server route/lifecycle changes also require `python -m unittest discover -s tests -p test_server.py`. The frontend runner uses its own loopback server, generated camera, local MediaPipe and `tests/effects-browser.mjs`. It saves desktop/tablet/phone and reduced-motion screenshots, fixed-source pixel comparisons and software timings under ignored `build/frontend-skills/`.

Verify all six distinct image outputs and their actual input transitions: palette cycles, repeated dither inversion, two-hand framing, liquid motion/decay, particle hold/scatter/release/morph and interruption. Test loss, crossings/reordering, cancellation, mode changes, reconnect and track shutdown. Synthetic gestures must be isolated from real generated-camera inference in deterministic sequences. Check keyboard focus, selected state, minimum touch targets, intro lifecycle, narrow layout, errors and local-only runtime requests. A successful build or a screenshot alone does not prove these behaviors.

Generated camera and synthetic landmarks do not prove physical latency, real webcam quality or parity with the reference videos. Never enable `--allow-device` or serial hardware during frontend checks. Read `docs/CAMERA.md` before separately authorized device work. Leave changes local unless asked to commit.
